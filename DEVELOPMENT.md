# Development

Use the existing checkout at `/workspace/FrameTrace`. Each cloud task is isolated;
create no extra Git worktree unless explicitly requested.

## Prerequisites

Python 3.12+, Node 22.13+ (24 also supported here), npm, FFmpeg/FFprobe, and Docker Compose.
Install Python packages from `services/api/requirements-dev.lock`, then the editable package
with `--no-deps`. The mobile package-lock pins npm dependencies. In this managed machine,
use `UV_CACHE_DIR=/workspace/.cache/uv` and `npm_config_cache=/workspace/.cache/npm` because
the default home caches are read-only. Keep TLS and signature verification enabled.

## Full local services

```sh
docker compose build api
docker compose up -d --wait postgres redis
docker compose up -d --wait api worker scheduler
```

On this cloud proxy, build with the system CA supplied only as a BuildKit secret:

```sh
docker build --secret id=proxy_ca,src=/etc/ssl/certs/ca-certificates.crt \
  -f infrastructure/Dockerfile -t frametrace-api:local .
docker compose up -d --wait api worker scheduler
```

The Dockerfile runs as an unprivileged user. Services bind to loopback by default.
Compose's database password is intentionally public local-development configuration.
Do not reuse it in a hosted deployment. API and workers share a private named media volume.
Database tables initialize when the API starts; wait for `/health` before ingestion.

```sh
curl --fail http://127.0.0.1:8000/health
.venv/bin/python scripts/make_fixtures.py var/fixtures
docker compose cp var/fixtures/reference.mp4 api:/app/var/reference.mp4
docker compose exec api python -m frametrace.cli ingest /app/var/reference.mp4 \
  --title 'Generated fixture 42' --publisher FrameTrace --actor local-operator \
  --rights-basis 'Original synthetic test footage generated by scripts/make_fixtures.py'
.venv/bin/python scripts/smoke_api.py
```

Ingestion is deliberately an operator CLI, not a publicly writable catalog endpoint.
A repeated content hash is rejected; don't reingest or reactivate revoked media blindly.
Only submit media you have permission to process. No user query enters the reference catalog.

For authorized media, pass an independently checked HTTPS `--source-url` if available.
Revoke with `python -m frametrace.cli revoke ID --actor local-operator --reason "Rights withdrawn"`. Revocation invalidates old result candidates.
Compose includes one Celery Beat scheduler: it dispatches/reconciles jobs every 15 seconds
and enqueues cleanup hourly. The configurable retention default is 24 hours; cleanup is
batched (1000 records per sweep). `python -m frametrace.cli cleanup` also runs it manually.
Successful and permanently failed workers delete clips immediately; retriable failures
retain clips. Never run multiple Beat processes against the same schedule file.

## Native mobile development

```sh
cd apps/mobile
npm ci
# Create .env using .env.example; set EXPO_PUBLIC_API_URL to a device-reachable API.
npm run typecheck
npx expo install --check
npx expo start --dev-client
```

Use a trusted development network or authenticated HTTPS tunnel to reach the backend from
a physical device. Loopback on a phone points to the phone. The default Compose binding
cannot be reached from another device; configure an explicit development binding/tunnel.
Use HTTPS for hosted APIs. Cleartext development networking may require development-only
native configuration; never weaken release network policy.

If Expo's online compatibility endpoint is blocked, `EXPO_OFFLINE=1 npx expo install --check`
checks versions against the installed SDK's bundled native-module manifest. It does not
perform the React Native Directory's online maintenance check. Request `api.expo.dev`
and `reactnative.directory` access in environment settings when needed; do not bypass policy.

```sh
npx expo export --platform android --platform ios
# With your own EAS project and signing/provisioning configured:
npx eas-cli build --profile development --platform android
npx eas-cli build --profile development --platform ios
```

Bundle export is not a signed native build, an install, or a device test. The package IDs
are placeholders pending ownership and branding checks. No store publication is configured.

## Fast backend-only iteration

`FRAMETRACE_EXECUTION=local .venv/bin/uvicorn frametrace.app:app` uses SQLite and in-process
background work. It has no automatic recovery scheduler. Default execution is Celery: run
Redis, worker and scheduler together. The database/outbox retains accepted jobs during a
broker outage and recovers them after restoration. Local disk/database persistence is
required; this is not multi-region disaster recovery. See TESTING.md.

## Reliability checks

The API accepts optional `X-Submission-Token`: a client-generated, secret random token
(43–128 URL-safe characters). It is also the job access capability; never log it. The
mobile app uses Expo Crypto and persists it in SecureStore before sending. Retrying the
same bytes with that token returns the existing ID and current status. Different bytes
return 409. Idempotency ends when the job is deleted/expired. Legacy tokenless callers
continue to work, but cannot deduplicate a response-lost initial submission.

The middleware caps total request bytes at the file limit plus 128 KiB multipart overhead,
spools to a private bounded temporary file before multipart parsing, and admits four
concurrent uploads per API process. Exceeding the size returns 413; admission returns 429
with Retry-After. These are not distributed per-user rate limits.

Worker claims use an atomic DB lease, owner fencing and a three-attempt budget. A lease
lasts at least 120s, longer than the 90s Celery task hard limit. Stale/duplicate deliveries
cannot commit results or delete another owner's file. Expired leases and unpublished
accepted jobs are redispatched with a 30s publication cooldown. API/worker hosts need
synchronized clocks. Local in-process execution does not have Celery's hard time limit.

For a local development outage exercise only:

```sh
.venv/bin/python scripts/smoke_recovery.py --exercise-outage
```

This briefly stops this project's scheduler, workers and Redis, submits/retries a real
fixture, restores services in `finally`, and verifies eventual recognition. Do not run
against production or while another developer depends on those local processes.

## Optional accounts and private object storage

Read docs/PHASE_3_ACCOUNTS_STORAGE.md before configuring external services. Defaults remain
guest/local storage. Server settings are documented in services/api/.env.example; mobile
public settings are in apps/mobile/.env.example. Never add credentials to either example.
Uvicorn can load an ignored server file with `--env-file services/api/.env`; Compose passes
the documented FRAMETRACE_* and server AWS credential variables from the shell/root .env.
Keep server signing credentials and DB passwords out of EXPO_PUBLIC_* variables.

For runtime CA trust in this managed cloud only:

```sh
FRAMETRACE_CA_BUNDLE_FILE=/etc/ssl/certs/ca-certificates.crt \
  docker compose -f compose.yaml -f compose.cloud-ca.yaml up -d --wait api worker scheduler
```

This mounts a public trust bundle; it does not enable destinations or supply credentials.
Use normal Compose when no custom runtime trust is needed. No cloud settings were changed.

## Native share development

The local Expo module lives under apps/mobile/modules/frametrace-share; checked-in config
plugins regenerate Android filters and the iOS extension target. Generated apps/mobile/android
and ios directories are ignored. Keep native source edits in the module/plugin templates.
Prebuild can replace generated directories: preserve any manual generated edits first.

```sh
cd apps/mobile
npm ci
npx expo prebuild --no-install
npm run native:verify
npm run typecheck
npm test
cd ../..
.venv/bin/python scripts/test_native_share.py
.venv/bin/python scripts/build_android.py
```

The Java-only check needs full JDK 17 (not just a Java runtime). Set FRAMETRACE_JDK17_HOME
if it is not discovered through JAVA_HOME or the installed task cache. The ARM64 debug
builder additionally needs Android 37.0, build-tools 37.0.0, NDK 27.1.12297006, CMake 3.22.1
and platform-tools. They are installed at /workspace/.cache/android-sdk in this instance;
set ANDROID_HOME to an existing compatible SDK in another machine. It checks the official
Gradle checksum and preserves existing cache properties outside its own proxy adapters.

The Android build is currently blocked by proxy denial of repo.reactnative.dev. Add that
host in environment settings before retrying; don't downgrade RN or bypass verification.
No emulator or APK success is claimed. The iOS build requires macOS/Xcode and a real team
with App Groups, plus the native device checks in MOBILE_RELEASE.md.

The evaluated share library's host-launch technique was not adopted. The custom extension
uses only a local save/complete flow; users open FrameTrace themselves. Receiving shares
requires a native build; installing JS dependencies or opening Expo Go is insufficient.

## Local operator review

Apply migrations in filename order before deploying updated server code; phase 9 adds
`supabase/migrations/202611180002_catalog_audit.sql`. Local API/CLI initialization creates
missing tables and performs existing execution-row backfill. No hosted migration is run here.

```sh
.venv/bin/python -m frametrace.cli catalog --limit 20
.venv/bin/python -m frametrace.cli catalog --include-revoked --offset 20
.venv/bin/python -m frametrace.cli catalog-audit --reference-id REFERENCE_ID
.venv/bin/python -m frametrace.cli feedback-summary --days 30
```

Ingest/revoke now require `--actor`; revoke also requires `--reason`. Actor labels are
operator-supplied metadata, not authenticated identities. CLI access requires trusted
server DB credentials; do not publish these commands as an unauthenticated admin service.
See docs/PHASE_9_OPERATOR_REVIEW.md for output fields and audit/aggregation limits.

Local PostgreSQL validation now checks all five migrations/eight tables, client CRUD denial and RLS under a temporary read grant. The PostgreSQL runner includes feedback/operator and concurrent-feedback cases; see docs/PHASE_10_POSTGRES_VALIDATION.md. These checks require disposable local database creation, not hosted credentials.

The Android helper now supports `--variant debug` (default, Metro) and `--variant internal-preview` (bundled release variant with development signing). APK verification/delivery instructions and API configuration are in docs/PHASE_11_ANDROID_TEST_APK.md. A GitHub Actions build is configured; no successful APK build is claimed yet.
